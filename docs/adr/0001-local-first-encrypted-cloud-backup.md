# 本機為正、雲端只存加密備份

消費紀錄（發票、品項、比對報告）是敏感個資，而本專案的資料庫是長期典藏——
平台品項明細只保存近 6 個月，本機資料毀損即永久遺失，所以備份是必要的。
我們決定：**本機 SQLite 是唯一正式儲存層；雲端（Google Drive）只存 AES-256
加密後的備份包，明文永不上雲**。密碼由使用者自行保管，不寫入任何檔案。

## Considered Options

- **雲端硬碟直接同步明文**——最省事，但消費紀錄明文躺在雲端，帳號或共用設定
  出錯即全部暴露。否決。
- **純本機＋外接硬碟**——最私密，但要自備硬體、靠紀律執行，實務上容易斷。
  否決（保留為加密上雲之外的自選補充）。

## Consequences

- 未來功能一律受此約束：不做 hosted dashboard、不做雲端資料庫、儀表板維持
  本機靜態檔案且**不自動外連**（頁面自己不發任何對外請求；使用者主動點擊的
  外部連結——如店家的 Google 地圖搜尋——不在此限，但點擊即等於把該筆資訊
  交給對方服務）。
- **明確例外：地圖檢視頁（map.html）**。使用者自行開啟時載入 OpenStreetMap
  圖磚（可視範圍會傳給圖磚伺服器）；店家座標由 `geocode` 一次性向 Nominatim
  查**稅籍營業地址**（公開商工資料）後快取在本機。消費資料本身永遠不出去；
  主儀表板維持零外連。
- `state/einvoice.json`（登入 cookie）連加密備份都不收——等同帳號本體，
  且數小時即失效，沒有備份價值。
- 密碼遺失＝備份全部不可讀，屬接受的風險（本機正本仍在時可重新產生備份包）。

# 檢視走靜態檔案、寫回走本機服務（同頁雙模式）

儀表板升級為全能查詢工具後，唯一靜態頁面做不到的事是「把店家歸類寫回
categories.local.json」。我們決定：**檢視維持 file:// 靜態檔案（開檔即用、零維運）；
要整理分類時以 `twcrawl serve` 起本機服務（Python 內建 http.server，零新相依、
只綁 localhost），同一套頁面偵測協定——file:// 唯讀＋規則片段複製，serve 模式
長出「歸類→存檔」按鈕，寫回規則檔並自動重生 data.js**。這是 ADR-0001
「儀表板維持本機靜態檔案」的細化，不是牴觸：服務不對外、明文不離機。

## Considered Options

- **純靜態＋複製貼上**——不用服務，但「複製→貼檔→重跑 export→重新整理」的
  迴圈對照著清單整理幾十家店時摩擦太大。否決（保留為 file:// 模式的後備）。
- **全面改走 serve**——連日常查看都先起服務，備份包解開也不能直接開頁；
  查詢面靜態已足，為寫回一件事拖累每天的路徑。否決。
- **CLI 互動歸類（twcrawl classify）**——零服務最省工，但沒有金額與常買品項的
  視覺脈絡，與查詢工具的定位不搭。否決。

## Consequences

- 頁面 JS 以協定（file:// 或 http://localhost）偵測能力，同一套 HTML 不維護兩份。
- serve 只在整理分類時運行，日常檢視仍是雙擊開檔；服務沒起，頁面照樣能看。
- data.js 因全能查詢加入品項全欄位與發票號碼（本機明文、gitignored）；
  **載具號碼與 raw JSON 永不進 data.js**——與 ADR-0001 的紅線一致。
- 日後規則管理再複雜化（改別名、改非必要判準），就擴充 serve 的寫回面，
  不動檢視路徑。
